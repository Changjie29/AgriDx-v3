# 自动版本更新规则

用户于 2026年10月13日确认：知识库内容更新统一增加补丁号，不再因数量大或覆盖新机型自动增加次版本。版本使用三个整数，不使用小数：3.4.8 的下一补丁是 3.4.9。

| 更新类型 | 命令类型 | 递进方式 |
| --- | --- | --- |
| 新增、修正知识条目、手册、来源、索引、覆盖品牌与机型 | knowledge | X.Y.Z → X.Y.(Z+1) |
| 修复已有功能 | fix | 补丁 |
| 兼容重构、性能、样式、文案与维护 | maintenance | 补丁 |
| 新增可用系统功能，如照片诊断、报告导出、知识审核管理 | feature | X.(Y+1).0 |
| 不兼容接口、数据或运行方式变化 | breaking | (X+1).0.0 |

当前阶段仍遵守用户已设置的 **3.4.9 上限**。脚本不会越界，也不会把 feature 或 breaking 偷换为补丁。需要更高版本时，先由用户明确调整上限和对应检查。历史编号保持不变。

## 执行方式

完成一批授权改动后，在任务分支执行：

```powershell
npm.cmd run version:update -- --kind knowledge --batch kb-20261013-a --summary "扩充本批农机资料" --dry-run
npm.cmd run version:update -- --kind knowledge --batch kb-20261013-a --summary "扩充本批农机资料"
npm.cmd run check:version
```

脚本自动计算版本，同步 package.json、锁文件两处根版本、README 当前版本和 CHANGELOG 最新条目，同时保存 version-batches.json。依赖版本、手册版次和历史记录不替换。日期使用上海时区。

每批使用唯一 ID；同批修正重复运行沿用该版本，不重复增加日志。旧批次不能在后续发布中复用。重复运行不会自动替换说明，需在该版 CHANGELOG 中补充最终交付与真实验证结果。同批多种改动选最高级别，不把增量相加；知识内容扩充本身始终为 knowledge。

并行分支合入前同步最新 main，协调批次 ID 和版本记录。发生版本冲突时不能简单保留某一方；按共同发布范围重整批次及日志。脚本不猜测文件改动是否破坏兼容，由执行者在 PR 写明所选类型和理由。

## 自动化边界

这是执行者调用的自动计算与同步命令，不是每次 commit 自动升版。AGENTS.md 要求后续任务使用本规则；现有 check:version 与 verify 持续检查版本一致性和上限。脚本不自动提交、推送、合并、建标签、建 Release 或部署。GitHub 保存和现有 main 开发站发布分别沿用原约定。

只需安装 Node 即可运行脚本及专用测试：`node --test tests/version-update.test.mjs`。每次提交补充与改动相关的检查，主线合入前完成项目要求的验证。
