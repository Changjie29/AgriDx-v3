# 网页自动加载新版本

2026-10-17，批次`auto-load-releases-20261017`，3.5.1。

## 自动同步边界

GitHub `main`仍是唯一发布来源。PR检查、审阅合入及现有部署完成后，开发站和腾讯正式站各自加载其已发布版本；不自动合并未经审阅的PR、不把分支草稿或未核验资料直接上线，也不同步用户私有记录到GitHub。

客户端启动时立即检查，之后每30秒检查；恢复前台、联网及窗口重新聚焦时立即检查。开发站读取`dev-preview.json`，正式站读取`deployment.json`，不需要用户说“继续”或点击刷新。构建、排队及服务器部署有实际耗时，整体为检查通过后的分钟级同步，不是逐键瞬时发布。

## 不打断当前工作

- 首页、知识页可安全自动载入，保留完整URL筛选及浏览器中已保存的记录；不清理localStorage或私有会话。
- 诊断请求/记忆读写中、问题草稿、未保存设备档案或检查进度存在时延期；保存、清空草稿或结束操作后自动重查最新发布并继续。已保存且内容非空的设备档案不阻止更新。
- 模型页选有本地照片、GLB、参考对象文字或正在读取模型时延期，避免丢失只能留在当前页面的文件；移除这些本地内容或离开该页后继续。
- 管理控制台和未知页面不强制载入，以免打断管理操作；回到知识页等安全页面后自动继续。

## 一致性和失败处理

Vite同时向应用常量和HTML的`agridx-build-commit`元标识写入当前完整Git提交。无Git元数据的普通本地构建仍可使用，但不启用自动更新；本地开发模式也不启用。

检查只访问当前站点同源HTTPS/HTTP地址，不接受重定向、无效40位提交、无效版本或更低版本。请求不使用缓存并附加时间戳；新HTML的提交必须匹配目标，再次核对发布记录后才执行载入。新部署在检查过程中前进时，放弃旧目标，下一轮采用最新目标。

每次检查最多12秒且只有一个在途任务，网络中断/403/无效内容保留现有可用页面并等待后续检查。后台不检查，组件卸载取消请求、定时器和监听器。sessionStorage、URL提交标识及内存记录共同防止CDN旧HTML造成反复刷新；禁用存储也不无限重载。

旧网页中已经运行的3.5.0及更早脚本无法被服务端隔空替换，首次需重新打开/载入一次3.5.1页面；此后该页面自行检测并自动载入后续已发布构建。本轮交付会打开已部署的新页面，不把“工作流已成功”单独当作客户端已切换证明。

## 本轮验证

更新控制流、输入保护及实际构建身份分别由`release-updater.test.ts`、`update-safety.test.ts`和`build-identity.test.ts`验证。控制流测试使用可控浏览器运行时，不冒充真实桌面/手机交互验收。完整verify、跨平台CI、PR合入及公网提交/网页资源核对以实际交付回执为准；电脑操控工具当前无法可靠读取浏览器地址，未完成真实浏览器自动换版演练。
