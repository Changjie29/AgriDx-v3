# Sites /chat 路由修复

- 日期：2026-10-04（上海）。
- Sites 项目：`appgprj_6ab5efd42cc48191a3bee1276e02c952`，公开访问范围保持不变。
- 基线 Sites 源码提交：`5860164cae84d29460d02a6879652f677eb53850`（保存版本 12）。
- 应用版本：沿用同轮部署的 `2.2.2`；源 main 提交与知识库计数保持原值。

## 原因与修复

React Router 已定义聊天页，但 Worker 原样把 `/chat` 交给资产绑定，依赖部署元数据中的 SPA 回退。实际直接访问返回 404，而旧资产测试对任何路径返回 HTML，无法发现该问题。

Worker 在处理 API 后，将 `/chat` 与尾斜杠变体的 GET/HEAD 请求内部映射到根入口 `/`，保留请求方法、查询和头部。浏览器 URL 仍是聊天路径。API、模型别名和静态资源继续使用原路径规则。

测试改用仅根入口与模型存在、其他路径返回 404 的资产模拟；额外使用构建出的真实 HTML 验证聊天路径、查询参数和 HEAD 空正文。线上复验脚本扩充到 `/chat`、`/chat/` 与带查询参数的 GET/HEAD。

## 验证与发布边界

生产构建 `npm run build:sites` 通过，前端类型检查与 Worker 导出检查通过，仍为 20 个来源、165 条归档知识、174 个片段。`npm run test:sites` 的 12 项测试全部通过，包含严格资产模拟下的聊天路径回归及既有 API、模型与检索检查。保留既有首页包体积提示。

源码记录与部署结果分别保留。重新发布通过原生 Sites 保存及部署工具完成，其返回的版本与状态为发布证据，部署回执保存在忽略的 `.outputs/chat-route-deployment.json`。本轮更新推送至 Sites 源码仓库；未向 GitHub 仓库提交或推送。

本轮线上 HTTP 检查受到云环境网络规则阻止：代理对 `https://agridx.xyz/chat` 的 CONNECT 返回 403，尚未到达网站，不能据此判断修复后的页面状态。当前也没有可用的浏览器控制工具，浏览器渲染未核验。允许目标域名后可执行 `npm run verify:sites` 复验。
