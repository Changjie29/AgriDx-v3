# 品牌—型号—组件—零部件分层导航

更新：2026-10-09（上海日期）。本文件规定现有证据的浏览方式，不是新增维修手册或已完成整机性能覆盖的声明。

## 数据与边界

- `sources.json`仍维护来源、原件明确的型号、版本和适用边界；`entries.jsonl`仍维护知识卡编号及定位。维修事实只保存在原Markdown编号段中。
- `hierarchy.json`只维护导航：组件名称、零件名称及现有`entry_id`的关联。不得写故障原因、处理流程、参数或第二份事实摘要，不改变来源的型号范围。该文件的`schema_version`是导航格式版次，与项目版本独立。
- 一个条目可涉及多个组件或零件，计数必须按`entry_id`去重。零件关联表示“此段涉及该部位”，不能解释成“此零件已损坏”或完整因果链。不能把一段中的所有症状和所有零件配对生成故障结论。
- 组件及零件归属须人工核对知识段与已有证据。`evidence_terms`只检查零件确实在原段中出现，是必要条件；关键词出现本身不是故障确诊或正确归属的充分依据。
- 条目只定位到组件时`part_ids`留空，浏览器显示零件待核实；不填造件号、结构、配置或兼容性。没有本机资料的组件显示资料缺口，零计数不能说明该系统运行正常。
- 资料索引、核验、机型背景和缺口进入资料导航；安全操作、日常维护、配套系统边界按原`entry_type`展示。`faultCount`仅统计原“维护/故障知识”类别，该类别含维护条目，不能称为已核验故障种类数或性能覆盖率。
- 型号原名来自来源或条目明确的型号子集；系列、平台、待核实范围分别标识，不补后缀。同册多个型号或别名不代表配置等价。驾驶室、驱动、排放、市场及版本等原限制随条目展示。
- 配套导航系统独立浏览，不能把其控制器、天线或自动转向资料挂为另一个品牌整机的已验证部件。

## API

`GET /api/knowledge/catalog`返回现有条目数、来源数、型号/范围数、分层目录及覆盖限制，默认不返回正文。品牌按现有归档名称保留，不把品牌别名数量当厂家数量。

选择品牌和来源中的型号后调用`GET /api/knowledge/catalog?brand=东方红&model=LF804S`；可依次追加`component=electrical&part=starter`。正文从已有知识卡读取，同时返回来源编号、链接、PDF物理页/印刷页定位、版次、配置和适用边界。未知型号、没有关联证据的零件不得回退到相似机型。

1w+是待完成的扩充目标，统计单位待确认。当前资料和导航数量以索引实际统计为准；全性能覆盖仍需逐机型补足手册、部件资料、运行症状与对应策略，并逐条核验证据。

## 维护与验收

新增或调整正式条目时，按[条目整理规范](../../条目整理规范.md)先更新来源、知识卡及条目索引，再维护`hierarchy.json`中的稳定编号关联。新增零件须写清名称及原知识段已有的检索词；删除条目时同步删除导航关联。

运行`python3 知识库/工具/校验索引.py`、`npm test`与`npm run build:server`。服务启动额外校验导航编号唯一、组件和零件存在、所有正式条目有导航关系及每个零件有原段文字依据。回归检查完整型号筛选、配置子集隔离、资料缺口及原始正文/来源一致性。另检查实际目录API和机型问答，不能以计数替代功能验证。
