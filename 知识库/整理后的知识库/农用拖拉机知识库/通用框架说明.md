# 农用拖拉机通用知识框架

更新：2026-10-13（上海），项目3.6.0；框架格式版次1。

先按通用系统、性能目标和运行表现组织知识，再匹配品牌、完整型号及配置读取原证据。通用的是分类与问诊方式，维修事实继续保留来源支持的机型范围。

## 当前交付

`通用框架.json`包含15个系统、36项性能目标、37类运行表现、6个诊断阶段和46条既有知识关联。36×6形成216个资料格；它们表示资料关联和待补项，不是216项已验证性能或故障。

系统包含整机作业、发动机与进排气、燃油、冷却、润滑、起动电气、离合传动、液压悬挂、转向、制动、行走前桥轮胎、PTO、驾驶室保护、配套导航及排气后处理。选装及专用系统按实车配置纳入；整机作业另需记录机具、土壤与负载等工况。

表现分别组织起动机不转、转动慢、发动机难着车，也区分动力不足与传动打滑、制动能力下降与跑偏、照明异常与整车断电。别名用于查找同一表现，不推断损坏零件。

## 六阶段与矩阵

| 阶段 | 需要的证据 |
| --- | --- |
| `normal` 正常功能与基准 | 匹配配置的功能、指标、单位、限值与测量工况 |
| `symptom` 故障表现 | 能够区分的运行现象及伴随条件 |
| `cause` 候选原因 | 原资料明确的候选，不升级为确诊 |
| `check` 检查与排除 | 检查方向、支持和排除条件；完整程序仍须核对 |
| `action` 条件化处置 | 匹配原因与配置的维护、修理或专业支持要求 |
| `retest` 恢复验收 | 复测项目、工况及合格依据 |

矩阵显示“有线索”或“待补”。有线索仅表示该阶段关联了原知识段，不证明完整程序、判定参数、机型适用或实车结果。本批没有将故障表提升为正常性能基准或修复验收证据，因此这两阶段保留待补。不计算全性能覆盖率，不用零格判断机器正常。

未选机型时展示跨机型资料格与信息收集问题，不返回诊断正文。选择型号后，矩阵与正文采用同一型号、组件、零部件及表现筛选。某机型缺少相应资料时保留缺口，不借其他型号策略填充。

## 文件与维护规则

- `systems`：稳定系统编号、名称、对应导航组件、配置说明与性能目标。
- `symptoms`：稳定表现编号、名称、别名、系统/性能关联和工况追问。
- `links`：现有`entryId`、表现/性能编号及阶段核对词；不保存原因、策略、参数或第二份正文。
- `stages`：六阶段定义；`questions`：共同的身份、工况与既有记录收集问题。

事实仍由`entries.jsonl`定位原Markdown知识卡，来源、页码、版次、精确型号子集及配置条件随原条目返回。通用框架不加入维修来源或条目索引，不增加26来源、1213条归档计数。

本批关联人工对照了原知识卡编号段。核对词出现是必要条件，不自动证明完整语义；运行校验检查编号、目标、原组件关系和核对词，后续仍须阅读正文。关系表示证据定位，不把同段所有症状和所有零件配对成因果结论。

## 浏览与API

知识页提供通用运行表现选择、工况追问、带表现问诊和按系统展开的性能矩阵；下方保留品牌—型号—组件—零部件浏览。

```text
GET /api/knowledge/catalog?symptom=starter-stopped
GET /api/knowledge/catalog?brand=东方红&model=LF804S&symptom=starter-stopped
GET /api/knowledge/catalog?brand=久保田&model=M6060&symptom=aftertreatment-alert&driveConfiguration=4WD
```

可选`configuration=CAB|ROPS`、`driveConfiguration=2WD|4WD`、`emissionStage=国三|国四`。明确填写时只返回登记了相同元数据的证据，未知条件保留缺口；不从年款、品牌或外观补推配置。更换品牌或型号会清除旧配置筛选；序列号、市场及版本等文字限制仍须核对。

未知表现或型号返回404，错误值、重复参数及缺失父级返回400。开发预览复用同一数据与服务逻辑，不访问生产接口。

## 后续新增与验收

1. 沿原整理规范取得并核对来源、机型、配置和证据页，将事实整理到知识卡与原索引。
2. 定义目标、表现、工况问题及配置范围，不生成通用检测参数。
3. 阅读编号段，分别确认表现、性能、阶段和组件关联，登记条目编号与核对词；缺少的正常/验收依据保留待补。
4. 同步导航与通用关联，执行下列检查，再验证实际API、问答和桌面/手机交互。过期引用须修复，不能静默忽略。
